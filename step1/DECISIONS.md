# Step 1 decisions

## S1 (2026-11-06)
- **S1-1 One exponent.** All λ1 use `p=1`. lyap.lyapunov always draws 4 start columns and keeps the first, so λ1 is the same for every p. Test (iii) shows a match to the stored p=4 values within 4e-12 relative. This cuts the cost about fourfold.
- **S1-2 No observation noise.** The configured environment has `observation_noise=True` (base_cfg.py:24). The measurement must be deterministic for JVPs, and task1c used none, so the policy's observation is built without noise. Action noise is also off (actor mean).
- **S1-3 Noisy commands.** The seed is the trajectory's index within its arena (0–3), so every model on an arena sees the same sequence. Noise is added to rows START+1…399 (forecast steps 2–368); step 1 keeps the recorded command, as in the policy condition. The std is computed over all 10,000 CSV rows (including the zero rows at resets), with ddof 0.
- **S1-4 λ1_cl start directions.** These are lyap.lyapunov's draw in the (h, s) coordinates, padded with zero in the 12 previous-command coordinates. Those coordinates enter the tangent norm, which gives a finite-time offset that vanishes with length (test ii: +3e-3 /s at gain 0.3 and +3e-4 /s at 0.1, against a true value of 5 /s).
- **S1-5 Imagined return.** The 12 weighted terms of `_compute_imagination_reward_terms`, times step_dt, summed over closed-loop steps 2–368.
  - The velocity command stays fixed per recorded segment: no resampling, no interval pushes, no termination resets.
  - Air- and contact-time buffers start at zero at step 2.
  - The uncertainty penalty (weight −1; nonzero only for five-head models) is reported apart as `ret_unc`, not added. Head-flagged terminations are counted (`n_term`), not acted on.
  - The authors' `dof_acc_l2` uses observation slice 12:24, which holds the joint positions, not the velocities (anymal_d_flat.py:105). This is reproduced as written: the authors' own method is called.
- **S1-6 Divergence.** λ1_pol, λ1_noise and r̄J use the float32 rollout's divergence step. λ1_cl uses its own float64 trajectory. A non-finite λ is also set to +inf.
- **S1-7 Probe scope.** The probe times score_gru only. Weight loading and compression (`compute.build`) are not included.

## S2 (2026-11-06)
- **S2-1 RSSM step map.** The state is (GRU latent, last predicted state). Every RSSM run has a categorical latent. The plan's "means" is taken as the rollout's own choice: the prior's mode (argmax one-hot), never sampled. The mode is piecewise constant in h, so its derivative is zero. rssm.py's straight-through term is left out of the derivative, because it would give the derivative of the class probabilities, not of the rollout. Its arithmetic, 1 + p − p, is kept in the values, so predictions are bitwise equal. A Gaussian latent would use its mean, but no such run exists.
- **S2-2 Window state.** MLP and Transformer carry 32 states and the 32 joint commands of the same rows, as the plan says. The oldest command is not read. Under recorded commands, the command coordinates leave the window within 32 steps. This is a finite-time offset, as in S1-4. Start directions are lyap's draw in n = 1,824 (557 for the RSSM).
- **S2-3 Transformer derivative.** torch 2.2's fused encoder kernel and its flash attention have no forward-mode derivative. Inside λ1 only, the Transformer runs in training mode (every dropout is 0) with the plain attention kernel. Float32 rollouts and the E values use the reproduction's evaluation path. JVP against finite differences agrees within 4e-9.
- **S2-4 Divergence under recorded commands.** `score_arch` reports raw values. Non-finite values become +inf. `div_rec` (S1's rule on the float32 rollout) and `lam_div` (the float64 Benettin trajectory became non-finite) are added, and no value is replaced because of them. **S3 must register** how a baseline that diverges under recorded commands enters AR1 and AR2. Conservative recommendation: keep its values, with +inf ranked last, and report the count.
- **S2-5 Test (vi) scope.** All 26 runs were checked, not one per class. The comparison is of predictions only.
- **S2-6 Training threads.** At 2 threads, the copy reproduces the stored curves bit for bit. 1 or 4 threads drift by about 1e-5 within 50 iterations. Recommendation for S3's job: train one run at a time at 2 threads (9.6 h), which is the reproduction's own setting. Two at a time would save only about 1.5 h.
